# Словарь курса

Каждая запись содержит готовую простую опору и точный критерий. Словарь не отправляет ученика искать отсутствующее определение.

| Термин | Простое объяснение | Точная опора | Первое занятие |
|---|---|---|---:|
| **frontend — передняя часть** | понимает исходный язык и сообщает ошибки | лексер, парсер, разрешение имён, проверка типов и диагностика | 1 |
| **middle-end — средняя часть** | анализирует и оптимизирует программу независимо от конкретного процессора | работает с IR, CFG, SSA и машинно-независимыми проходами | 1 |
| **backend — задняя часть** | выражает результат средствами целевой машины | понижение, выбор инструкций, регистры, ассемблер и объектный код | 1 |
| **IR — промежуточное представление** | внутренний язык компилятора | структура с явным контрактом, удобная конкретному анализу или преобразованию | 1 |
| **линковка** | соединение объектных файлов и библиотек | разрешает внешние символы и формирует исполняемый файл или библиотеку | 1 |
| **лидер** | первая инструкция нового блока | entry, цель перехода или инструкция сразу после терминатора | 2 |
| **базовый блок** | кусок кода, выполняемый подряд | максимальная последовательность с входом только в первую инструкцию и выходом через последний терминатор | 2 |
| **терминатор** | последняя инструкция, выбирающая следующий блок | `branch`, `goto`, `return`, `throw` и аналогичные инструкции | 2 |
| **fall-through — проваливание** | переход к следующему размещённому блоку без явного `goto` | ребро CFG, которое всё равно должно быть зафиксировано | 2 |
| **максимальность** | нельзя безопасно приклеить соседнюю инструкцию | блок не делят без причины и не объединяют через лидера/терминатор | 2 |
| **CFG — control-flow graph** | граф возможных переходов управления | вершины — базовые блоки, рёбра — возможный непосредственный переход | 3 |
| **entry — вход** | первый блок функции | начальная вершина анализа достижимости | 3 |
| **exit — выход** | блок, после которого функция не продолжает обычное выполнение | обычно содержит `return`, `throw` или иной выход | 3 |
| **predecessor — предшественник** | блок с ребром в текущий блок | `u ∈ pred(v)` тогда и только тогда, когда `u → v` | 3 |
| **successor — последователь** | блок, который может выполняться следующим | `v ∈ succ(u)` тогда и только тогда, когда `u → v` | 3 |
| **доминирование** | блок нельзя обойти по пути к другой вершине | `D dom B`, если каждый путь от entry к B содержит D | 4 |
| **строгое доминирование** | доминирование другого блока, не самого себя | `D sdom B`, если D dom B и D ≠ B | 4 |
| **путь** | последовательность связанных рёбрами вершин | начинается в entry для определения доминирования | 4 |
| **неподвижная точка** | состояние, которое следующая итерация уже не меняет | остановка итерационного data-flow алгоритма | 4 |
| **контрпуть** | один путь, обходящий кандидата | достаточен, чтобы опровергнуть доминирование | 4 |
| **idom — непосредственный доминатор** | ближайший строгий доминатор блока | единственный `D`, который доминируется всеми остальными строгими доминаторами `B` | 5 |
| **дерево доминаторов** | дерево ближайших обязательных предков | ребро `idom(B) → B`; предки `B` совпадают с его строгими доминаторами | 5 |
| **join — точка слияния** | блок с несколькими входящими путями | обычно имеет несколько достижимых predecessors, но это ещё не определение DF | 5 |
| **dominance frontier — фронт доминирования** | место, где полное доминирование `X` заканчивается | `Y ∈ DF(X)`, если `X` доминирует predecessor `Y`, но не строго доминирует `Y` | 5 |
| **runner — поднимаемый кандидат** | predecessor, который поднимают по `idom` | добавляет join в DF встреченных узлов до `idom(join)` | 5 |
| **SSA — static single assignment** | форма IR с одним определением каждого SSA-имени | повторные присваивания исходной переменной получают новые версии | 6 |
| **SSA-value — SSA-значение** | результат одной конкретной инструкции | имеет единственный def и набор uses; не равно storage-слоту | 6 |
| **φ-функция** | выбирает вход по ребру, по которому пришло управление | один подписанный operand на каждый predecessor блока | 6 |
| **definition block** | блок, создающий новую версию переменной | обычный def или уже вставленная φ считаются определениями | 6 |
| **iterated DF — итерационный фронт** | достижимость от definition blocks по отношению DF | worklist добавляет новые φ-блоки до неподвижной точки | 6 |
| **dominator-tree walk** | обход дерева доминаторов | родитель обрабатывается до всех блоков, которые он доминирует | 7 |
| **стек версий** | текущие доступные SSA-имена одной исходной переменной | верхушка используется при чтении | 7 |
| **push** | положить новое определение на стек | выполняется при φ-def и обычном def | 7 |
| **pop** | снять определения, созданные в покидаемом блоке | восстанавливает состояние для соседнего поддерева | 7 |
| **φ-аргумент** | значение на конкретном входящем ребре | заполняется из верхушки стека в predecessor | 7 |
| **def-use** | связь определения с каждым использованием результата | ребро от SSA-def к инструкции-use | 8 |
| **data dependence** | результат одной операции нужен другой | для pure SSA-операций следует из operand def-use | 8 |
| **value number** | идентификатор уже известного значения | одинаковые доказанно эквивалентные выражения получают один VN | 8 |
| **канонический ключ** | нормализованное описание выражения | opcode, тип, flags и VN операндов | 8 |
| **наблюдаемый эффект** | изменение, которое программа или среда может заметить | store, I/O, volatile/atomic, исключение, неизвестный call и т.п. | 8 |
| **constant folding — свёртка** | вычисляет известную операцию во время компиляции | `3*4 → 12` при сохранении точной семантики типа и overflow | 9 |
| **constant propagation — распространение** | переносит известную константу от def к uses | заменяет use SSA-значения известным literal | 9 |
| **worklist — рабочая очередь** | хранит инструкции, которые могли измениться | повторная обработка продолжается до отсутствия новых фактов | 9 |
| **executable edge — исполнимое ребро** | ребро, которое возможно при известных фактах | нужно SCCP; обычный propagation сам по себе не моделирует частичную достижимость | 9 |
| **SCCP — sparse conditional constant propagation** | совместно анализирует значения и исполнимые рёбра | optional extension с lattice `unknown/constant/overdefined` | 9 |
| **DCE** | dead code elimination | удаляет ненужные инструкции без необходимых эффектов | 10 |
| **UCE** | unreachable code elimination | удаляет блоки, не достижимые от entry | 10 |
| **живой root** | операция, результат или эффект которой должен сохраниться | return, observable store/call и другие корни mark phase | 10 |
| **наблюдаемый эффект** | изменение поведения, видимое программе/среде | I/O, memory write, volatile/atomic, trap и т.п. | 10 |
| **φ cleanup** | исправление φ после изменения predecessors | удаление входов и упрощение одно-входовых φ | 10 |
| **call site — место вызова** | инструкция вызова вместе с окружающим блоком | блок обычно делится на before-call и continuation | 11 |
| **callee — вызываемая функция** | функция, тело которой клонируется | её параметры, блоки и значения получают отображение в caller | 11 |
| **formal/actual — параметр и аргумент** | имя в callee и значение в call site | каждый formal заменяется соответствующим actual SSA-value | 11 |
| **continuation block — продолжение** | блок после встроенного вызова | все return клона переходят сюда | 11 |
| **profitability — выгодность** | оценка пользы и стоимости | не влияет на semantic legality, но ограничивает рост кода | 11 |
| **артефакт** | проверяемый промежуточный результат | blocks, CFG, Dom, SSA или версия IR после pass | 12 |
| **инвариант** | условие корректности состояния | например, один terminator на block или один def на SSA name | 12 |
| **verifier** | механическая проверка инвариантов | останавливает pipeline на первом некорректном состоянии | 12 |
| **pass order** | порядок преобразований | выход одного прохода является входом следующего | 12 |
| **первичная ошибка** | самый ранний нарушенный инвариант | её исправление обычно устраняет каскад вторичных симптомов | 12 |
| **back edge** | ребро из latch обратно в header | `n→h` является back edge для natural loop, если `h dom n` | 13 |
| **header** | единая контролирующая точка входа natural loop | доминирует все блоки natural loop | 13 |
| **latch** | блок, содержащий back edge в header | может быть несколько latch blocks | 13 |
| **preheader** | выделенный внешний блок перед header | единственный внешний predecessor canonical header | 13 |
| **irreducible region** | циклическая область с несколькими независимыми входами | не представляется одним natural loop с доминирующим header | 13 |
| **DFS number — номер обхода** | порядок первого посещения вершины DFS | задаёт parent relation и обратный порядок обработки кандидатов | 14 |
| **back predecessor** | источник ребра к DFS-предку-кандидату | начальное содержимое pool возможного loop header | 14 |
| **non-back predecessor** | остальные predecessors региона | через них pool расширяется к представителям уже свёрнутых областей | 14 |
| **Union-Find — непересекающиеся множества** | хранит представитель свёрнутого региона | `find(v)` возвращает текущего представителя, `union` объединяет регионы | 14 |
| **loop nesting tree — дерево вложенности** | родительские отношения найденных loop regions | внутренний loop становится ребёнком внешнего | 14 |
| **basic IV** | базовая индуктивная переменная | `i_next=i+step`, где init/step loop-invariant | 15 |
| **derived IV** | линейная функция basic IV | `j=a*i+b` при invariant a,b | 15 |
| **recurrence** | правило перехода к следующему значению | описывает init и update | 15 |
| **closed form** | формула значения на итерации k | например `i(k)=init+k*step` | 15 |
| **strength reduction** | замена дорогой операции дешёвым обновлением | создаёт собственную recurrence для derived IV | 15 |
| **loop invariant — инвариант цикла** | значение не меняется между итерациями | operands определены вне цикла или уже доказаны invariant | 16 |
| **hoist — вынос** | перемещение инструкции в preheader | сохраняет value, effects, exceptions и dominance uses | 16 |
| **speculation — спекулятивное выполнение** | операция выполняется на пути, где раньше могла не выполняться | допустимо только при доказанной безопасности раннего выполнения | 16 |
| **aliasing — совпадение адресов** | разные ссылки могут обозначать одну память | store через alias способен изменить результат load | 16 |
| **dominance of uses — доминирование использований** | новое определение доступно каждому use | место hoist должно доминировать ordinary uses и нужные exit uses | 16 |
| **unroll** | дублирование тела нескольких итераций | уменьшает loop-control overhead и требует remainder | 17 |
| **peeling** | выделение первых/последних итераций | убирает особый случай из основного loop | 17 |
| **splitting** | деление диапазона итераций | например, до и после границы/условия | 17 |
| **distribution** | разделение statements одного loop на несколько loops | требует сохранения dependences | 17 |
| **fusion** | объединение соседних совместимых loops | требует одинаковых диапазонов и безопасного порядка | 17 |
| **loop SSA** | SSA с φ для значений, переходящих между итерациями | initial input из preheader и updated input из latch | 18 |
| **legality** | доказательство сохранения поведения | предусловия transformation выполнены | 18 |
| **profitability** | ожидаемая практическая польза | не входит в доказательство корректности | 18 |
| **analysis invalidation** | старый результат анализа больше не соответствует IR | CFG rewrite обычно инвалидирует Dom/DF/loop info | 18 |
| **final verifier** | последняя механическая проверка | CFG, φ, dominance, defs, effects и use validity | 18 |
| **таймбокс** | фиксированный лимит времени на этап | после лимита состояние сохраняется и работа продолжается по регламенту | 19 |
| **рубрика** | критерии начисления баллов | позволяет отделить структуру, SSA и legality | 19 |
| **transfer — перенос** | применение знания на новом примере | показывает понимание, а не узнавание ответа | 19 |
| **completion gap** | незавершённый обязательный артефакт | отмечается явно, а не маскируется догадкой | 19 |
| **первичная ошибка** | самая ранняя причина каскада | определяет первую тему ремонта | 19 |
| **repair** | целенаправленное исправление конкретной ошибки | ошибка → invariant → правило → новый пример | 20 |
| **контрпример** | случай, опровергающий неверное общее правило | одного достаточно для отказа от ложного утверждения | 20 |
| **повторная трасса** | повтор алгоритма с записью состояний | проверяет механику, а не память финального ответа | 20 |
| **retrieval** | воспроизведение без подсказки | измеряет доступность знания | 20 |
| **стоп-правило** | условие завершения ремонта | два новых примера подряд без исходной ошибки | 20 |

# Словарь курса

Каждая запись содержит простое объяснение и точный критерий. Английское название приведено после русского только там, где оно помогает читать документацию и исходный код.

| Термин | Простое объяснение | Точная опора | Первое занятие |
|---|---|---|---:|
| **Передняя часть компилятора** (*frontend*) | понимает исходный язык и сообщает ошибки | лексический и синтаксический анализ, разрешение имён, проверка типов и диагностика | 1 |
| **Средняя часть компилятора** (*middle-end*) | анализирует и оптимизирует программу независимо от конкретного процессора | работает с IR, CFG, SSA и машинно-независимыми проходами | 1 |
| **Задняя часть компилятора** (*backend*) | переводит результат в команды целевой машины | понижение представления, выбор инструкций, распределение регистров, ассемблер и объектный код | 1 |
| **IR — промежуточное представление** | внутренний язык компилятора | структура с явным контрактом, удобная для конкретного анализа или преобразования | 1 |
| **Линковка** | соединяет объектные файлы и библиотеки | разрешает внешние символы и создаёт исполняемый файл или библиотеку | 1 |
| **Лидер** | первая инструкция нового базового блока | вход функции, цель перехода или инструкция после условной/безусловной передачи управления | 2 |
| **Базовый блок** (*basic block*) | максимальная последовательность инструкций, выполняемая подряд | вход возможен только в первую инструкцию; после нормализации выход задаёт единственный терминатор | 2 |
| **Терминатор** | последняя инструкция нормализованного блока | `jump`, `branch`, `return` или `unreachable`; перечисляет все непосредственные пути управления | 2 |
| **Неявный переход к следующему блоку** (*fall-through*) | переход без записанного `goto` в линейном IR | при нормализации заменяется явным `jump` к следующему расположенному блоку | 2 |
| **Максимальность блока** | к блоку нельзя безопасно присоединить соседнюю инструкцию | присоединение нарушило бы единственный вход или прямолинейное выполнение | 2 |
| **CFG — граф потока управления** (*control-flow graph*) | показывает возможные переходы между базовыми блоками | вершины — нормализованные блоки, рёбра — цели их терминаторов | 3 |
| **Входной блок** (*entry*) | первый блок функции | начальная вершина анализа достижимости | 3 |
| **Выходной блок** (*exit*) | блок, после которого обычное выполнение функции не продолжается | заканчивается терминатором без обычных последователей | 3 |
| **Предшественник** (*predecessor*) | блок, из которого можно непосредственно перейти в текущий | `u ∈ pred(v)` тогда и только тогда, когда существует ребро `u → v` | 3 |
| **Последователь** (*successor*) | блок, который может выполняться следующим | `v ∈ succ(u)` тогда и только тогда, когда существует ребро `u → v` | 3 |
| **Доминирование** | блок нельзя обойти на пути к другой вершине | `D dom B`, если каждый путь от входа к `B` содержит `D` | 4 |
| **Строгое доминирование** | доминирование другого блока, но не самого себя | `D sdom B`, если `D dom B` и `D ≠ B` | 4 |
| **Путь** | последовательность вершин, соединённых рёбрами | в определении доминирования рассматриваются пути от входного блока | 4 |
| **Неподвижная точка** (*fixed point*) | состояние, которое следующая итерация уже не меняет | условие завершения итерационного потокового анализа | 4 |
| **Путь-контрпример** | путь, который обходит предполагаемый доминатор | одного такого пути достаточно, чтобы опровергнуть доминирование | 4 |
| **Непосредственный доминатор** (*idom*) | ближайший строгий доминатор блока | единственный строгий доминатор `D`, который доминируется всеми остальными строгими доминаторами блока | 5 |
| **Дерево доминаторов** (*dominator tree*) | дерево ближайших обязательных предков | ребро `idom(B) → B`; предки `B` совпадают с его строгими доминаторами | 5 |
| **Точка слияния** (*join*) | блок, в который приходят несколько путей | обычно имеет несколько достижимых предшественников, но этого недостаточно для определения DF | 5 |
| **Фронт доминирования** (*dominance frontier*) | граница области полного доминирования | `Y ∈ DF(X)`, если `X` доминирует некоторого предшественника `Y`, но не строго доминирует `Y` | 5 |
| **Текущий узел подъёма** (*runner*) | узел, который последовательно заменяют его `idom` | при вычислении DF точка слияния добавляется узлам до `idom` самой точки слияния | 5 |
| **SSA — форма единственного присваивания** (*static single assignment*) | каждое SSA-имя определяется ровно один раз | повторные присваивания исходной переменной получают разные версии | 6 |
| **SSA-значение** (*SSA value*) | результат одной конкретной инструкции | имеет единственное определение и набор использований; не является изменяемым хранилищем | 6 |
| **φ-функция** | выбирает значение по входящему ребру | имеет ровно один подписанный операнд для каждого достижимого предшественника блока | 6 |
| **Блок определения** (*definition block*) | блок, создающий новую версию значения | обычное определение и вставленная φ-функция оба считаются определениями | 6 |
| **Итерационный фронт доминирования** (*iterated DF*) | повторное применение отношения DF к блокам определений | рабочая очередь добавляет новые блоки с φ-функциями до неподвижной точки | 6 |
| **Обход дерева доминаторов** (*dominator-tree walk*) | обрабатывает определение раньше всех доминируемых использований | родитель дерева посещается до его потомков | 7 |
| **Стек версий** | хранит доступные версии одной исходной переменной | верхняя версия используется при чтении | 7 |
| **Добавление в стек** (*push*) | делает новое определение текущей версией | выполняется для результата φ-функции и обычного определения | 7 |
| **Удаление из стека** (*pop*) | убирает версии, созданные в покидаемом блоке | восстанавливает состояние для соседнего поддерева | 7 |
| **Аргумент φ-функции** | значение на конкретном входящем ребре | заполняется текущей верхней версией в блоке-предшественнике | 7 |
| **Связь определения с использованием** (*def-use*) | показывает, где используется результат конкретного определения | ребро идёт от SSA-определения к инструкции, которая читает его результат | 8 |
| **Зависимость по данным** (*data dependence*) | одной операции нужен результат другой | для чистых SSA-операций следует из связей операндов с их определениями | 8 |
| **Номер значения** (*value number*) | обозначает уже известное вычисленное значение | доказанно эквивалентные выражения получают одинаковый номер | 8 |
| **Канонический ключ** | нормализованно описывает выражение | содержит код операции, тип, флаги и номера значений операндов | 8 |
| **Наблюдаемый эффект** | изменение, которое может заметить программа или среда | запись в память, ввод-вывод, `volatile`, `atomic`, ошибка или вызов с неизвестными эффектами | 8 |
| **Свёртка констант** (*constant folding*) | вычисляет известную операцию во время компиляции | например, `3*4 → 12`, если сохранена точная семантика типа и переполнения | 9 |
| **Распространение констант** (*constant propagation*) | переносит известную константу от определения к использованиям | заменяет использование SSA-значения известным литералом | 9 |
| **Рабочая очередь** (*worklist*) | хранит инструкции, которые нужно пересчитать | обработка продолжается, пока новые факты не перестанут появляться | 9 |
| **Исполнимое ребро** (*executable edge*) | ребро, которое возможно при известных фактах | используется в SCCP для совместного анализа значений и достижимости | 9 |
| **SCCP — разреженное условное распространение констант** (*sparse conditional constant propagation*) | одновременно анализирует значения и исполнимость рёбер | использует состояния `не определено (⊥) / константа / переопределено (⊤)` | 9 |
| **DCE — удаление мёртвого кода** (*dead code elimination*) | удаляет ненужные вычисления без обязательных эффектов | сохраняет корни живости и все определения, от которых они зависят | 10 |
| **UCE — удаление недостижимого кода** (*unreachable code elimination*) | удаляет блоки, недостижимые из входа | после изменения переходов заново вычисляет достижимость | 10 |
| **Корень живости** (*live root*) | операция или значение, которое обязано сохраниться | например, возврат результата, наблюдаемая запись или вызов | 10 |
| **Сохраняемый эффект** | поведение, которое нельзя удалить как неиспользуемый результат | ввод-вывод, запись в память, `volatile`, `atomic`, ошибка выполнения и подобные действия | 10 |
| **Обновление φ-функций** (*phi cleanup*) | восстанавливает φ-функции после изменения предшественников | удаляет исчезнувшие входы и упрощает φ-функции с одним входом | 10 |
| **Место вызова** (*call site*) | инструкция вызова вместе с окружающим блоком | блок обычно делят на часть до вызова и блок продолжения | 11 |
| **Вызываемая функция** (*callee*) | функция, тело которой встраивают | её блоки, параметры и значения клонируют с новыми идентификаторами | 11 |
| **Параметр и аргумент** (*formal and actual argument*) | имя в вызываемой функции и переданное ему значение | каждый параметр заменяется соответствующим SSA-значением аргумента | 11 |
| **Блок продолжения** (*continuation block*) | блок, в котором продолжается вызывающая функция | все пути возврата из клона переходят в него | 11 |
| **Выгодность встраивания** (*inlining profitability*) | оценивает пользу и стоимость встраивания | не доказывает допустимость, но ограничивает рост кода | 11 |
| **Артефакт** | проверяемый промежуточный результат | например, список блоков, CFG, множества доминаторов, SSA или версия IR после прохода | 12 |
| **Инвариант** | условие корректности состояния | например, один терминатор на блок или одно определение SSA-имени | 12 |
| **Проверка инвариантов** (*verifier*) | механически проверяет контракт представления | останавливает цепочку обработки на первом некорректном состоянии | 12 |
| **Порядок проходов** (*pass order*) | задаёт последовательность анализов и преобразований | выход одного прохода становится входом следующего | 12 |
| **Первичная ошибка** | самое раннее нарушение инварианта | её исправление обычно устраняет каскад более поздних симптомов | 12 |
| **Обратное ребро** (*back edge*) | ребро из замыкающего блока в заголовок естественного цикла | `n→h` является таким ребром, если `h` доминирует `n` | 13 |
| **Заголовок цикла** (*header*) | единая контролирующая точка входа в естественный цикл | доминирует все блоки этого цикла | 13 |
| **Замыкающий блок** (*latch*) | блок, из которого идёт обратное ребро в заголовок | у одного цикла может быть несколько замыкающих блоков | 13 |
| **Предвходной блок** (*preheader*) | отдельный внешний блок перед заголовком | является единственным внешним предшественником канонического заголовка | 13 |
| **Несводимая область** (*irreducible region*) | циклическая область без единого доминирующего входа | имеет разные внешние входные вершины и не имеет заголовка, доминирующего всю область | 13 |
| **Номер DFS-обхода** (*DFS number*) | номер первого посещения вершины поиском в глубину | задаёт родителя и обратный порядок обработки кандидатов | 14 |
| **Кандидат заголовка** | вершина, относительно которой проверяют циклическую область | обрабатывается после потенциальных внутренних заголовков | 14 |
| **Рабочее множество области** (*worklist*) | представители вершин и уже свёрнутых областей, которые ещё нужно исследовать | изменяется после каждого извлечения и добавления предшественников | 14 |
| **Структура непересекающихся множеств** (*Union-Find*) | хранит представителя свёрнутой области | `find(v)` возвращает представителя, а `union` объединяет области | 14 |
| **Дерево вложенности циклов** (*loop nesting tree*) | показывает родительские отношения найденных циклов | внутренний цикл становится дочерним узлом внешнего | 14 |
| **Базовая индуктивная переменная** (*basic induction variable*) | изменяется на постоянный шаг в каждой итерации | имеет вид `i_next = i + step`, где начальное значение и шаг неизменны в цикле | 15 |
| **Производная индуктивная переменная** (*derived induction variable*) | является линейной функцией базовой переменной | имеет вид `j = a*i + b`, где `a` и `b` неизменны в цикле | 15 |
| **Рекуррентное соотношение** (*recurrence*) | задаёт переход к следующему значению | содержит начальное значение и правило обновления | 15 |
| **Замкнутая формула** (*closed form*) | выражает значение через номер итерации | например, `i(k)=init+k*step` | 15 |
| **Снижение стоимости операций** (*strength reduction*) | заменяет дорогую операцию дешёвым обновлением | создаёт отдельное рекуррентное соотношение для производной переменной | 15 |
| **Инвариант цикла** (*loop invariant*) | не меняется между итерациями | его операнды определены вне цикла или уже доказаны неизменными | 16 |
| **Вынос инструкции** (*hoisting*) | перемещает инструкцию в предвходной блок | должен сохранять значение, эффекты, ошибки и доступность результата | 16 |
| **Раннее выполнение** (*speculation*) | выполняет операцию на пути, где раньше она могла не выполняться | допустимо только при доказанной безопасности | 16 |
| **Возможное совпадение адресов** (*aliasing*) | разные ссылки могут указывать на одну память | запись через одну ссылку способна изменить результат загрузки через другую | 16 |
| **Доминирование использований** (*dominance of uses*) | новое определение доступно каждому использованию | место выноса должно доминировать все точки, где нужен результат | 16 |
| **Разворачивание цикла** (*unrolling*) | дублирует тело нескольких итераций | уменьшает расходы на управление циклом и требует обработки остатка | 17 |
| **Отделение крайних итераций** (*peeling*) | выносит первые или последние итерации в отдельный код | убирает особый случай из основного цикла | 17 |
| **Разделение диапазона** (*loop splitting*) | делит диапазон итераций на части | например, до и после границы или условия | 17 |
| **Распределение цикла** (*loop distribution*) | разделяет инструкции одного цикла на несколько циклов | должно сохранять все зависимости | 17 |
| **Слияние циклов** (*loop fusion*) | объединяет соседние совместимые циклы | требует одинаковых диапазонов и безопасного порядка операций | 17 |
| **SSA-форма цикла** (*loop SSA*) | использует φ-функции для значений между итерациями | начальный вход приходит из предвходного блока, обновлённый — из замыкающего | 18 |
| **Допустимость** (*legality*) | доказывает сохранение поведения программы | все предусловия преобразования должны быть выполнены | 18 |
| **Выгодность преобразования** (*transformation profitability*) | оценивает практическую пользу преобразования | не входит в доказательство корректности | 18 |
| **Устаревание анализа** (*analysis invalidation*) | означает, что прежний результат больше не соответствует IR | изменение CFG обычно требует пересчитать Dom, DF и сведения о циклах | 18 |
| **Итоговая проверка инвариантов** (*final verifier*) | проверяет состояние после всех преобразований | контролирует CFG, входы φ-функций, определения, доминирование, эффекты и допустимость использований | 18 |
| **Ограничение времени** (*timebox*) | задаёт фиксированное время на этап | после его окончания состояние сохраняется и работа продолжается по регламенту | 19 |
| **Рубрика** | задаёт критерии начисления баллов | позволяет отдельно оценить структуру, SSA и допустимость преобразований | 19 |
| **Перенос навыка** (*transfer*) | применяет знание к новому примеру | показывает понимание, а не узнавание знакомого ответа | 19 |
| **Незавершённый этап** (*completion gap*) | явно отмечает отсутствующий обязательный результат | не маскируется догадкой; для продолжения записывается отдельное допущение | 19 |
| **Первая причина ошибки** | самый ранний пробел, вызвавший каскад ошибок | определяет первую тему для исправления | 19 |
| **Работа над ошибкой** (*repair*) | устраняет одну конкретную причину ошибки | ошибка → нарушенный инвариант → правильное правило → новый пример | 20 |
| **Контрпример** | опровергает неверное общее правило | одного корректного контрпримера достаточно для отказа от ложного утверждения | 20 |
| **Повторная трасса** | повторяет алгоритм с записью промежуточных состояний | проверяет механику вычисления, а не память конечного ответа | 20 |
| **Воспроизведение без подсказки** (*retrieval*) | извлекает знание из памяти без опоры на конспект | показывает, доступен ли навык самостоятельно | 20 |
| **Условие завершения** (*stop rule*) | показывает, когда работу над ошибкой можно закончить | исходная ошибка не повторяется в двух новых примерах подряд | 20 |

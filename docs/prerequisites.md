# Обязательные предпосылки

Эта страница закрывает понятия, которые нужны внутри курса, но не заслуживают отдельного полного занятия. После каждого блока есть минимальная проверка.

## Binding, storage и value

- **Binding — привязка имени**: связь исходного идентификатора с объявлением в scope. Два текста `x` могут ссылаться на разные bindings.
- **Storage — место хранения**: слот локальной переменной, адрес памяти, поле объекта. Оно может менять содержимое.
- **IR value — результат вычисления**: значение конкретной инструкции.
- **SSA value** — IR value с единственным определением.

Они не взаимозаменяемы: binding живёт по правилам языка, storage — runtime, SSA value — по def-use/dominance контракту IR.

**Проверка:** параметр `x`, стековый слот для `x` и `%x3 = add ...` — три разных объекта.

## Минимальная семантическая модель

Разрешение имён отвечает «к какому объявлению относится use?». Проверка типов — «допустима ли операция и какой у неё тип?». Анализ эффектов — «читает/пишет ли инструкция память, выполняет I/O, может ли бросить исключение?».

## DFS и SCC

**DFS — поиск в глубину** ведёт состояния `unvisited / active / finished`, parent и номер первого посещения. Ребро в active-предка является DFS back edge, но natural-loop back edge дополнительно требует dominance.

**SCC — strongly connected component, сильносвязная компонента**: максимальное множество вершин, где из каждой можно дойти до каждой. SCC размера больше одного или self-loop указывает циклическую область, но не гарантирует единый loop header.

Мини-трасса для `A→B→C→B`: DFS numbers `A=0,B=1,C=2`; SCC — `{B,C}`.

## Worklist и неподвижная точка

Worklist хранит объекты, чьи факты надо пересчитать. Если факт изменился, зависящие объекты возвращаются в очередь. Алгоритм заканчивается, когда очередь пуста и новое применение transfer function не меняет состояние.

## Canonical loop form

В обязательных цикловых задачах по умолчанию:

- header доминирует тело;
- есть выделенный preheader;
- back edge приходит из latch;
- exits подписаны отдельно;
- SSA φ имеет вход из preheader и из latch.

Если форма не дана, сначала явно создай её и исправь φ/CFG.

## Loop-carried dependence

**Loop-carried dependence — межитерационная зависимость** связывает операцию итерации `i` с операцией другой итерации. Пример:

```text
a[i] = a[i-1] + 1
```

Чтение `a[i-1]` зависит от записи предыдущей итерации; произвольная перестановка итераций незаконна. **Distance** здесь равно 1. Зависимости внутри той же итерации имеют distance 0.

Для loop transformation всегда выпиши producer, consumer, direction/distance и проверяемый порядок.

# Пробный зачёт: вариант 2

Используй [контракт учебного IR v1](../ir-contract.md) и [80-балльную рубрику](answers-and-rubrics.md#аналитическая-шкала-комплексной-работы). Сначала выполни работу самостоятельно, затем открывай полный эталон по этапам.

## Теоретическая часть

1. Чем CFG отличается от дерева доминаторов?
2. Сформулируй определение фронта доминирования через конкретного предшественника.
3. Почему вход φ-функции относится к ребру, а не просто к тексту внутри блока?
4. Когда вызов, который не изменяет память, всё равно нельзя считать чистым?
5. Чем естественный цикл отличается от несводимой сильносвязной компоненты?

<details>
<summary>Эталон теоретической части</summary>

1. CFG хранит возможные непосредственные переходы управления. Дерево доминаторов хранит отношение ближайшего обязательного предка; его ребро не означает передачу управления.
2. `Y ∈ DF(X)`, если существует `P ∈ pred(Y)`, для которого `X dom P`, но `X` не строго доминирует `Y`.
3. φ выбирает операнд по тому, с какого предшественника пришло управление. Поэтому доступность значения проверяется в конце соответствующего предшественника на ребре `P→Y`.
4. `readonly`-вызов может читать изменяемую память, завершиться ошибкой или иным образом иметь наблюдаемое чтение. Отсутствие записи не делает его автоматически `pure`.
5. Естественный цикл имеет обратное ребро `n→h`, где `h dom n`, и единый заголовок. Несводимая SCC имеет разные внешние входные вершины и не имеет вершины, доминирующей всю область как единый заголовок.

</details>

## Практическая часть

```text
p = input
n = input
i = 0
s = 0
goto head

head:
if i >= n goto exit

test:
t = 4 * n + 1
if p goto use else skip

use:
idx = 4 * i
v = load A[idx]
s = s + v + t
goto cont

skip:
dead = t * 0
goto cont

cont:
i = i + 1
goto head

exit:
print s
return
```

Построй базовые блоки и CFG, затем вычисли Dom, `idom` и DF. Переведи программу в SSA, выполни допустимые свёртку констант, LVN и DCE, после чего проанализируй цикл. Для LICM и снижения стоимости операций явно перечисли необходимые предпосылки.

<summary>Полный эталон практической части</summary>

## 1. Блоки и CFG

Нормализованные блоки:

```text
PRE:
  p = input
  n = input
  i = 0
  s = 0
  jump H

H:
  branch i >= n, EXIT, TEST

TEST:
  t = 4*n + 1
  branch p, USE, SKIP

USE:
  idx = 4*i
  v = load A[idx]
  s = s + v + t
  jump CONT

SKIP:
  dead = t*0
  jump CONT

CONT:
  i = i + 1
  jump H

EXIT:
  print s
  return
```

Рёбра:

```text
PRE → H
H → TEST, EXIT
TEST → USE, SKIP
USE → CONT
SKIP → CONT
CONT → H
```

| Блок | `succ` | `pred` |
|---|---|---|
| PRE | {H} | ∅ |
| H | {TEST,EXIT} | {PRE,CONT} |
| TEST | {USE,SKIP} | {H} |
| USE | {CONT} | {TEST} |
| SKIP | {CONT} | {TEST} |
| CONT | {H} | {USE,SKIP} |
| EXIT | ∅ | {H} |

## 2. Dom

```text
Dom(PRE)  = {PRE}
Dom(H)    = {PRE,H}
Dom(TEST) = {PRE,H,TEST}
Dom(USE)  = {PRE,H,TEST,USE}
Dom(SKIP) = {PRE,H,TEST,SKIP}
Dom(CONT) = {PRE,H,TEST,CONT}
Dom(EXIT) = {PRE,H,EXIT}
```

## 3. `idom`

```text
idom(H) = PRE
idom(TEST) = H
idom(USE) = TEST
idom(SKIP) = TEST
idom(CONT) = TEST
idom(EXIT) = H
```

## 4. DF

```text
DF(PRE)  = ∅
DF(H)    = {H}
DF(TEST) = {H}
DF(USE)  = {CONT}
DF(SKIP) = {CONT}
DF(CONT) = {H}
DF(EXIT) = ∅
```

## 5. SSA

```text
PRE:
  p0 = input
  n0 = input
  i0 = 0
  s0 = 0
  jump H

H:
  i1 = φ[PRE: i0, CONT: i2]
  s1 = φ[PRE: s0, CONT: s3]
  branch i1 >= n0, EXIT, TEST

TEST:
  t0 = 4*n0 + 1
  branch p0, USE, SKIP

USE:
  idx0 = 4*i1
  v0 = load A[idx0]
  s2 = s1 + v0 + t0
  jump CONT

SKIP:
  dead0 = t0 * 0
  jump CONT

CONT:
  s3 = φ[USE: s2, SKIP: s1]
  i2 = i1 + 1
  jump H

EXIT:
  print s1
  return
```

φ для `s` в `CONT` обязательна: ветвь `USE` обновляет накопитель, а ветвь `SKIP` переносит прежнее значение.

## 6. Константы, LVN и DCE

`dead0=t0*0` сворачивается в `0` и удаляется DCE. Сам блок `SKIP` остаётся, пока `p0` неизвестно.

Внутри отдельных блоков нет повторного выражения, которое LVN могла бы устранить. Вычисление `t0=4*n0+1` выполняется в `TEST` один раз на итерацию и является кандидатом LICM, а не результатом LVN между блоками.

Если `p0` доказано истинным или ложным, только тогда можно упростить ветвление, выполнить UCE, обновить `pred(CONT)` и φ-функцию `s3`.

## 7. Естественный цикл

`H dom CONT`, поэтому `CONT→H` — обратное ребро. Тело естественного цикла:

```text
{H, TEST, USE, SKIP, CONT}
```

`PRE` — предвходной блок; `EXIT` находится вне цикла.

## 8. LICM для `t0`

Проверки:

1. `n0` определено вне цикла — операнды инвариантны;
2. `mul` и `add` для `i32` чисты и не завершаются ошибкой;
3. раннее выполнение в `PRE` безопасно даже при нулевом числе итераций;
4. `PRE` доминирует все использования результата после переноса.

Следовательно, можно создать в `PRE`:

```text
t_pre = 4*n0 + 1
```

заменить `t0` на `t_pre` и удалить старое определение.

## 9. Загрузка

`load A[idx0]` нельзя вынести: `idx0` зависит от `i1` и меняется между итерациями. Даже при постоянном адресе понадобились бы доказательства безопасности памяти, отсутствия совпадающих записей и отсутствия новой ошибки на пути с нулём итераций.

## 10. Снижение стоимости `idx0`

`i` имеет начальное значение 0 и шаг 1. Для `idx=4*i`:

```text
idx(0) = 0
idx(k+1) = idx(k) + 4
```

Один вариант:

```text
PRE:
  idx_init = 0
  ...
H:
  idx1 = φ[PRE: idx_init, CONT: idx2]
  ...
USE:
  v0 = load A[idx1]
  ...
CONT:
  idx2 = idx1 + 4
  i2 = i1 + 1
  jump H
```

Дополнительное обновление `idx2` выполняется и на ветви `SKIP`. Оно является чистым и безопасным, но выгодность такого изменения при редко выполняемой `USE` нужно оценивать отдельно.

## 11. Устаревание анализов

Перенос `t0`, удаление `dead0` и добавление рекуррентного `idx` без изменения рёбер сохраняют CFG, Dom, `idom`, DF и структуру цикла. Они требуют обновить def-use, факты номеров значений, живость и повторить SSA verifier.

Удаление ветви после доказанного `p0` меняет CFG и требует пересчитать все анализы, зависящие от путей, а также исправить φ-функцию в `CONT`.

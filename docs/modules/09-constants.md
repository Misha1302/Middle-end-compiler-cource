# Занятие 9. Свёртка и распространение констант

> Сначала простой propagation, затем — граница SCCP

[← Карта курса](../course-map.md) · [Предыдущее занятие](08-dependencies-and-lvn.md) · [Следующее занятие](10-dce-uce-and-pass-order.md)

## Результат занятия

Ты различаешь folding и propagation, доводишь простое распространение констант до неподвижной точки и корректно запускаешь cleanup после упрощения branch.

**Перед началом:** SSA, def-use и φ-семантика. **SCCP не требуется для обязательной части.**

## Зачем это вообще нужно

Константа полезна не только в месте определения. Подстановка может открыть новое вычисление, затем сделать условие известным, а это — удалить путь и упростить φ. Поэтому проходы усиливают друг друга и обычно повторяются.

## Термины до заданий

| Термин | Простое объяснение | Точная опора |
|---|---|---|
| **constant folding — свёртка** | вычисляет известную операцию во время компиляции | `3*4 → 12` при сохранении точной семантики типа и overflow |
| **constant propagation — распространение** | переносит известную константу от def к uses | заменяет use SSA-значения известным literal |
| **worklist — рабочая очередь** | хранит инструкции, которые могли измениться | повторная обработка продолжается до отсутствия новых фактов |
| **executable edge — исполнимое ребро** | ребро, которое возможно при известных фактах | нужно SCCP; обычный propagation сам по себе не моделирует частичную достижимость |
| **SCCP — sparse conditional constant propagation** | совместно анализирует значения и исполнимые рёбра | optional extension с lattice `unknown/constant/overdefined` |

## Первая модель

```text
x1 = 3
x2 = x1 + 4   -> propagation: 3 + 4 -> folding: 7
branch x2==7  -> true
```

После превращения branch в `goto` работа не закончена: нужны UCE, φ-repair и DCE.

## Разобранный пример: состояние за состоянием

```text
B0: c0 = 1; branch c0 == 1, B1, B2
B1: x1 = 5; goto B3
B2: x2 = 9; goto B3
B3: x3 = φ[B1:x1, B2:x2]; y1 = x3 + 2
```

| Шаг | Изменение | Новый факт |
|---|---|---|
| 1 | `c0` подставлен в условие | `1==1` |
| 2 | условие свёрнуто | branch всегда ведёт в B1 |
| 3 | B2 удалён UCE | `pred(B3)={B1}` |
| 4 | φ исправлена | `x3=x1`, затем `x3=5` |
| 5 | `y1=5+2` свёрнуто | `y1=7` |
| 6 | ненужные копии удалены DCE | стабильный IR |

## Формальное правило

Обычный propagation повторяет: взять известное SSA-значение, заменить его uses, выполнить допустимый folding, добавить изменившиеся users в worklist. CFG изменяется только когда условие доказано константным; после этого структурные инварианты чинятся немедленно.

SCCP расширяет модель двумя решётками — значений и достижимости рёбер — и изучается как углубление, а не как скрытое требование задачи A.

## Типичные ошибки

- Называть folding и propagation одним действием.
- Выполнять алгебру без проверки типа, overflow, NaN или исключений.
- Удалять ветвь, когда условие лишь «вероятно» известно.
- Оставлять φ со входом от удалённого predecessor.

## Проверка на выходе

**Чем folding отличается от propagation?**  
**Почему cleanup после branch обязателен?**  
**Что добавляет SCCP сверх обычного propagation?**

<details>
<summary>Короткие ответы</summary>

Folding вычисляет операцию, propagation переносит факт. CFG rewrite меняет predecessors, φ и анализы. SCCP одновременно учитывает lattice значений и исполнимость рёбер.

</details>

## Профессиональная граница

Реальные constant folders обязаны точно воспроизводить семантику целевого IR: ширину целых, poison/undef, floating-point flags и возможные traps.

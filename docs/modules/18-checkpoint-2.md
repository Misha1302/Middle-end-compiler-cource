# Занятие 18. Комплексная работа №2

> SSA-форма цикла, индуктивные переменные, LICM и снижение стоимости операций

[← Карта курса](../course-map.md) · [Предыдущее занятие](../modules/17-loop-transformations.md) · [Следующее занятие](../modules/19-mock-exam-1.md)

## Результат занятия

Ты проводишь полный разбор цикла и явно доказываешь допустимость каждого преобразования.

**Перед началом:** занятия 13–17.

## Зачем это вообще нужно

Проходы по циклам зависят от корректных CFG и SSA, а также от явных допущений о памяти. Эта работа проверяет всю цепочку, а не отдельные определения.

## Термины до заданий

| Термин | Простое объяснение | Точная опора |
|---|---|---|
| **SSA-форма цикла** (*loop SSA*) | использует φ-функции для значений между итерациями | начальный вход приходит из предвходного блока, обновлённый — из замыкающего |
| **Допустимость** (*legality*) | доказывает сохранение поведения программы | все предусловия преобразования должны быть выполнены |
| **Выгодность преобразования** (*transformation profitability*) | оценивает практическую пользу преобразования | не входит в доказательство корректности |
| **Устаревание анализа** (*analysis invalidation*) | означает, что прежний результат больше не соответствует IR | изменение CFG обычно требует пересчитать Dom, DF и сведения о циклах |
| **Итоговая проверка инвариантов** (*final verifier*) | проверяет состояние после всех преобразований | контролирует CFG, входы φ-функций, определения, доминирование, эффекты и допустимость использований |

Сначала прочитай объяснения. Затем закрой таблицу и перескажи термины своими словами. Это проверка понимания, а не попытка угадать определение.

## Ключевая схема

`CFG и структура цикла → проверка SSA → индуктивные переменные → кандидаты на вынос → доказательство допустимости → преобразования → перечень устаревших анализов → итоговая проверка инвариантов`

## Пошаговый разбор

В контрольном режиме первые 120 минут работа выполняется без подсказок. Правило «запросить помощь через 10–15 минут» для этого занятия не действует; разбор начинается только после сохранения самостоятельной попытки.

## Формальное правило

Каждый проход получает проверенный IR, выдаёт новую версию, перечисляет сохранённые и устаревшие анализы и проходит соответствующую проверку инвариантов.

## Типичные ошибки

- Использовать общий шаблон помощи внутри контрольной части.
- Выполнить LICM до доказательства существования предвходного блока и безопасности раннего выполнения.
- Снизить стоимость выражения без проверки начального случая.
- Не пересчитать сведения о циклах после изменения CFG.

## Задача A — по образцу

Для IR:

```text
n=input; i=0; s=0; k=4*n+1
head: if i>=n goto exit
t=4*n+1
idx=4*i+3
v=load A[idx]
s=s+v+t
i=i+1
goto head
exit: print s
```

Построй CFG, Dom, IDom, DF, естественный цикл и SSA для `i,s`.

<details>
<summary>Проверка задачи A — открывать после попытки</summary>

Заголовок содержит φ-функции `i1=φ[PRE:i0,L:i2]` и `s1=φ[PRE:s0,L:s2]`. Замыкающий блок обновляет `i`, а тело — `s`. Естественный цикл включает заголовок, тело и замыкающий блок; начальные значения находятся в предвходном блоке.

</details>

## Самостоятельная задача

Докажи или отвергни: заменить `t` на `k`, вынести загрузку, снизить стоимость вычисления `idx`, затем перечисли устаревшие анализы.

<details>
<summary>Проверка задачи B — открывать после попытки</summary>

`t` и `k` эквивалентны при одинаковых типах и правилах переполнения; `t` можно заменить и удалить. Загрузку нельзя вынести без неизменного адреса и доказательства отсутствия опасного совпадения адресов, потому что `idx` меняется между итерациями. Для `idx` начальное значение равно 3, шаг — 4.

Эти изменения не меняют CFG, но меняют связи определений и использований. Создание предвходного блока или изменение CFG делает недействительными результаты Dom и DF и сведения о циклах.

</details>

<details>
<summary>Короткие ответы</summary>

**Почему контрольная часть без помощи?**  
Она измеряет самостоятельное воспроизведение; помощь переносится в последующий разбор.

**Что делает результат анализа Dom недействительным?**  
Изменение рёбер или блоков CFG, способное изменить множество путей.

**Что проверяет итоговая проверка инвариантов?**  
Структуру CFG, соответствие входов φ-функций предшественникам, единственность определений, доминирование использований и допустимость эффектов и операндов.

</details>

## Как это устроено в промышленном компиляторе

Промышленный компилятор декларативно хранит сведения о сохранении анализов. В учебной работе достаточно явного журнала после каждого прохода.

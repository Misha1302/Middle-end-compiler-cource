# Занятие 2. Лидеры и базовые блоки

> Как разрезать линейный IR на максимальные прямолинейные участки и получить блоки с явными терминаторами

[← Карта курса](../course-map.md) · [Предыдущее занятие](../modules/01-pipeline-and-diagnostic.md) · [Следующее занятие](../modules/03-building-cfg.md)

## Результат занятия

Ты находишь все лидеры, строишь максимальные базовые блоки в линейной записи и затем нормализуешь каждый неявный переход в явный `goto`.

**Перед началом:** занятие 1; достаточно понимать метки, условный и безусловный переход. Перед решением зафиксируй [контракт учебного IR](../ir-contract.md#две-формы-записи-управления).

## Зачем это вообще нужно

Анализы CFG работают с блоками, а не с произвольными строками. Если разрезать код неверно, ребро может вести в середину блока. Если после разбиения не сделать неявные переходы явными, фраза «каждый блок заканчивается терминатором» станет двусмысленной.

## Термины до заданий

| Термин | Простое объяснение | Точная опора |
|---|---|---|
| **Лидер** | первая инструкция нового базового блока | вход функции, цель перехода или инструкция сразу после инструкции, меняющей обычное продолжение управления |
| **Базовый блок** (*basic block*) | максимальная последовательность инструкций, выполняемая подряд | вход возможен только в первую инструкцию; после нормализации выход задаёт единственный терминатор |
| **Терминатор** | последняя инструкция нормализованного блока, перечисляющая дальнейшие пути | `jump`, `branch`, `return` или `unreachable` |
| **Неявный переход к следующему блоку** (*fall-through*) | переход из конца блока к следующему расположенному блоку без записанного `goto` | существует только в линейной записи и при нормализации заменяется явным `jump` |
| **Максимальность блока** | к блоку нельзя присоединить соседнюю инструкцию без нарушения единственного входа или прямолинейного выполнения | границы определяются лидерами и инструкциями передачи управления, а не удобством рисунка |

Сначала прочитай объяснения. Затем закрой таблицу и перескажи термины своими словами. Это проверка понимания, а не попытка угадать определение.

## Ключевая схема

Линейный IR:

```text
1: x = input()
2: if x < 0 goto Lneg
3: y = x + 1
4: goto Lend
Lneg:
5: y = 1 - x
Lend:
6: return y
```

Лидеры: `1`, `3`, `5`, `6`.

После разбиения и нормализации:

```text
B0:
  x = input()
  branch x < 0, B2, B1

B1:
  y = x + 1
  jump B3

B2:
  y = 1 - x
  jump B3

B3:
  return y
```

В линейной записи переход `B2 → B3` был неявным. В нормализованном CFG-IR он стал обычным `jump`.

## Пошаговый разбор

| Шаг | Наблюдение | Новый лидер |
|---|---|---|
| 1 | первая инструкция функции | 1 |
| 2 | `Lneg` — цель условного перехода | 5 |
| 3 | после условного перехода выполнение может продолжиться строкой 3 | 3 |
| 4 | `Lend` — цель `goto` | 6 |
| 5 | строка после `goto` уже совпадает с целью `Lneg` | нового лидера нет |

Блоки линейной записи: `B0=[1,2]`, `B1=[3,4]`, `B2=[5]`, `B3=[6]`.

У `B2` нет записанного `goto`, но после строки 5 управление продолжалось строкой 6. Поэтому при нормализации в конец `B2` добавляется `jump B3`.

## Формальное правило

1. Добавь первую инструкцию функции в множество лидеров.
2. Добавь каждую цель явного перехода.
3. Добавь инструкцию сразу после условного или безусловного перехода, если она существует.
4. Отсортируй лидеры по линейному порядку. Каждый блок идёт от лидера до инструкции перед следующим лидером.
5. Определи выход каждого блока по последней исходной инструкции.
6. Если выполнение продолжалось в следующий расположенный блок без явного перехода, добавь `jump`.
7. Проверь нормализованный результат: каждый блок имеет ровно один терминатор, и терминатор стоит последним.

## Типичные ошибки

- Забыть инструкцию после условного перехода.
- Считать неявный переход отсутствием ребра CFG.
- Одновременно требовать терминатор у каждого блока и оставлять блок с обычным присваиванием в конце без объяснения формы IR.
- Разрезать каждую строку в отдельный блок и потерять максимальность.
- Оставить `goto` в середине блока.

## Задача A — по образцу

Разбей на блоки и затем нормализуй:

```text
1: a = input()
2: if p goto L1
3: a = 10
4: goto L2
L1:
5: a = 20
6: if q goto L2
7: a = 30
L2:
8: return a
```

<details>
<summary>Проверка задачи A — открывать после попытки</summary>

Лидеры: `1,3,5,7,8`. Блоки линейной записи: `[1,2]`, `[3,4]`, `[5,6]`, `[7]`, `[8]`.

Нормализованный IR:

```text
B0: a=input(); branch p, B2, B1
B1: a=10; jump B4
B2: a=20; branch q, B4, B3
B3: a=30; jump B4
B4: return a
```

У блока `B3` неявный переход заменён явным `jump B4`.

</details>

## Самостоятельная задача

Придумай два контрпримера:

1. ошибочное объединение инструкций через условный переход;
2. ненужное дробление двух последовательных арифметических инструкций.

Для каждого сначала покажи линейную запись, затем нормализованный CFG-IR.

<details>
<summary>Проверка задачи B — открывать после попытки</summary>

Объединять условный переход и инструкцию его ложного продолжения в один прямолинейный блок нельзя: при истинном условии эта инструкция не выполняется.

Дробление `x=1; y=x+2` на два блока без метки или перехода может сохранить поведение после добавления лишнего `jump`, но нарушает максимальность и создаёт ненужную вершину CFG.

</details>

## Проверь себя

**Почему цель перехода всегда лидер?**  

**Чем fall-through в линейной записи отличается от терминатора нормализованного блока?**  

**Что значит максимальный базовый блок?**

<details>
<summary>Короткие ответы</summary>

**Почему цель перехода всегда лидер?**  
Потому что управление может войти прямо в эту инструкцию, минуя предыдущие.

**Чем отличаются две формы?**  
В линейной записи переход к следующему блоку может быть не записан. После нормализации тот же путь представлен явным `jump`.

**Что значит максимальный базовый блок?**  
К нему нельзя добавить соседнюю инструкцию, не нарушив единственный вход или прямолинейное выполнение.

</details>

## Как это устроено в промышленном компиляторе

Промышленные IR обычно хранят блоки уже в нормализованной форме с явными терминаторами. Линейная запись с метками удобна как входное учебное представление, но перед анализами её нужно преобразовать без потери ни одного неявного перехода.

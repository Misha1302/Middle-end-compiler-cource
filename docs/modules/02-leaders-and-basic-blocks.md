# Занятие 2. Лидеры и базовые блоки

> Как разрезать линейный IR на максимальные прямолинейные участки

[← Карта курса](../course-map.md) · [Предыдущее занятие](../modules/01-pipeline-and-diagnostic.md) · [Следующее занятие](../modules/03-building-cfg.md)

## Результат занятия

Ты находишь все лидеры и строишь базовые блоки без входа в середину и выхода до последней инструкции.

**Перед началом:** занятие 1; достаточно понимать метки, условный и безусловный переход.

## Зачем это вообще нужно

Анализы CFG работают с блоками, а не с произвольными строками. Если разрезать код неверно, ребро может вести в середину блока или терминатор окажется не последним.

## Термины до заданий

| Термин | Простое объяснение | Точная опора |
|---|---|---|
| **Лидер** | первая инструкция нового базового блока | вход функции, цель перехода или инструкция сразу после терминатора |
| **Базовый блок** (*basic block*) | последовательность инструкций, которая выполняется подряд | вход возможен только в первую инструкцию, выход — через последний терминатор; блок нельзя расширить без нарушения этого свойства |
| **Терминатор** | последняя инструкция блока, выбирающая дальнейший путь | например, `branch`, `goto`, `return` или `throw` |
| **Переход к следующему блоку** (*fall-through*) | переход без явного `goto` к следующему расположенному блоку | это полноценное ребро CFG, которое нужно учитывать |
| **Максимальность блока** | к блоку нельзя безопасно присоединить соседнюю инструкцию | границы определяются лидерами и терминаторами, а не удобством записи |

Сначала прочитай объяснения. Затем закрой таблицу и перескажи термины своими словами. Это проверка понимания, а не попытка угадать определение.

## Ключевая схема

```text
1: x = input()
2: if x < 0 goto Lneg
3: y = x + 1
4: goto Lend
Lneg:
5: y = 1 - x
Lend:
6: return y
```

Лидеры: `1`, `3`, `5`, `6`.

## Пошаговый разбор

| Шаг | Наблюдение | Новый лидер |
|---|---|---|
| 1 | первая инструкция функции | 1 |
| 2 | `Lneg` — цель условного перехода | 5 |
| 3 | после условного перехода выполнение может продолжиться строкой 3 | 3 |
| 4 | `Lend` — цель `goto` | 6 |
| 5 | строка после `goto` уже совпадает с целью `Lneg` | нового лидера нет |

Блоки: `B0=[1,2]`, `B1=[3,4]`, `B2=[5]`, `B3=[6]`.

## Формальное правило

Алгоритм: собери множество лидеров, отсортируй их по линейному порядку, затем каждый блок продолжается от лидера до инструкции перед следующим лидером включительно. Проверь, что терминатор последняя инструкция блока.

## Типичные ошибки

- Забыть инструкцию после условного перехода.
- Считать переход к следующему расположенному блоку отсутствием ребра CFG.
- Разрезать каждую строку в отдельный блок и потерять максимальность.
- Оставить `goto` в середине блока.

## Задача A — по образцу

Разбей на блоки:

```text
1: a = input()
2: if p goto L1
3: a = 10
4: goto L2
L1:
5: a = 20
6: if q goto L2
7: a = 30
L2:
8: return a
```

<details>
<summary>Проверка задачи A — открывать после попытки</summary>

Лидеры: `1,3,5,7,8`. Блоки: `[1,2]`, `[3,4]`, `[5,6]`, `[7]`, `[8]`. Терминаторы: условный переход, `goto`, условный переход, переход к следующему блоку и `return`.

</details>

## Самостоятельная задача

Придумай два контрпримера: один для ошибочного объединения через условный переход и один для ненужного дробления двух последовательных арифметических инструкций.

<details>
<summary>Проверка задачи B — открывать после попытки</summary>

Объединение строк `2` и `3` одного блока неверно: при истинном условии строка 3 не выполняется. Дробление `x=1; y=x+2` на два блока без метки или перехода сохраняет поведение, но нарушает максимальность и создаёт лишнюю вершину CFG.

</details>

<details>
<summary>Короткие ответы</summary>

**Почему цель перехода всегда лидер?**  
Потому что управление может войти прямо в эту инструкцию, минуя предыдущие.

**Что значит максимальный блок?**  
К нему нельзя добавить соседнюю инструкцию, не нарушив правило входа или выхода.

**Является ли переход к следующему блоку ребром CFG?**  
Да, это непосредственная возможная передача управления.

</details>

## Как это устроено в промышленном компиляторе

В реальных IR встречаются `switch`, рёбра исключений и специальные блоки обработки исключений. Основной принцип не меняется, но набор терминаторов становится шире.

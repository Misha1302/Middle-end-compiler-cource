## Результат занятия

Ты строишь граф связей определений и использований SSA и выполняешь LVN с учётом типов, семантики операций и эффектов.

**Перед началом:** корректная SSA.

## Зачем это вообще нужно

Два выражения могут иметь одинаковый текст, но разные значения из-за типов, правил переполнения, памяти или эффектов. Нужно формально определить, когда вычисление действительно повторяется.

## Термины до заданий

| Термин | Простое объяснение | Точная опора |
|---|---|---|
| **Связь определения с использованием** (*def-use*) | показывает, где используется результат конкретного определения | ребро идёт от SSA-определения к инструкции, которая читает его результат |
| **Зависимость по данным** (*data dependence*) | одной операции нужен результат другой | для чистых SSA-операций следует из связей операндов с их определениями |
| **Номер значения** (*value number*) | обозначает уже известное вычисленное значение | доказанно эквивалентные выражения получают одинаковый номер |
| **Канонический ключ** | нормализованно описывает выражение | содержит код операции, тип, флаги и номера значений операндов |
| **Наблюдаемый эффект** | изменение, которое может заметить программа или среда | запись в память, ввод-вывод, `volatile`, `atomic`, исключение или вызов с неизвестными эффектами |

Сначала прочитай объяснения. Затем закрой таблицу и перескажи термины своими словами. Это проверка понимания, а не попытка угадать определение.

## Ключевая схема

```text
a0 = input
b0 = input
t1 = add i32 a0, b0
t2 = add i32 b0, a0
t3 = sub i32 a0, b0
```

Для обычного целочисленного `add` без различающихся семантических флагов ключи `t1` и `t2` можно канонизировать сортировкой номеров значений операндов. Для `sub` порядок сохраняется.

## Пошаговый разбор

| Инструкция | Ключ | Номер значения | Действие |
|---|---|---|---|
| `a0=input` | новый вход A | 1 | новое значение |
| `b0=input` | новый вход B | 2 | новое значение |
| `t1=add i32 a0,b0` | `(add,i32,1,2)` | 3 | новое значение |
| `t2=add i32 b0,a0` | `(add,i32,1,2)` | 3 | заменить на `t1` |
| `t3=sub i32 a0,b0` | `(sub,i32,1,2)` | 4 | новое значение |

Ключ обязан включать тип и семантические флаги. `add i32` и `add i64` не одно выражение.

## Формальное правило

LVN действует внутри одного базового блока и использует только факты, действующие в этой точке. Для операций с памятью нужна версия состояния памяти и контракт возможного совпадения адресов; вызов с неизвестными эффектами обычно делает прежние факты о памяти недействительными.

## Типичные ошибки

- Сортировать операнды некоммутативной операции.
- Игнорировать тип, правила переполнения или флаги упрощённой арифметики с плавающей точкой.
- Считать две инструкции загрузки `load p` одинаковыми, если между ними возможна запись или вызов с неизвестными эффектами.
- Путать ребро CFG с зависимостью по данным.

## Задача A — по образцу

Построй связи определений с использованиями и таблицу LVN для `a+b; b+a; a-b; a+b; 2*(a+b)`.

<details>
<summary>Проверка задачи A — открывать после попытки</summary>

Все `a+b` и `b+a` получают один номер значения при коммутативной семантике. `a-b` получает другой номер. `2*(a+b)` использует номер константы 2 и номер суммы; повтор такого выражения можно заменить.

</details>

## Самостоятельная задача

Добавь вызов с неизвестными эффектами между двумя инструкциями `load p`. Объясни, почему обычный LVN не имеет права объединять эти загрузки без контракта памяти.

<details>
<summary>Проверка задачи B — открывать после попытки</summary>

Неизвестный вызов может записать по адресу, совпадающему с `p`, поэтому вторая загрузка может вернуть другое значение. Нужен доказанный контракт отсутствия записи и модель возможного совпадения адресов либо MemorySSA.

</details>

<details>
<summary>Короткие ответы</summary>

**Из чего состоит ключ номера значения?**  
Из операции, типа, семантических флагов и номера значений операндов; для памяти также нужно учитывать её состояние.

**Когда можно сортировать операнды?**  
Только если операция коммутативна в точной семантике IR.

**Почему SSA не решает память автоматически?**  
Обычная SSA версионирует вычисленные значения, но разные загрузки и записи могут обращаться к одной области памяти.

</details>

## Как это устроено в промышленном компиляторе

Глобальная нумерация значений требует учитывать пути CFG, доминирование и состояние памяти; LVN намеренно ограничен одним блоком.

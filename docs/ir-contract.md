# Единый контракт учебного IR

Все задачи курса опираются на один контракт. Если конкретное условие явно задаёт другую семантику, оно имеет приоритет.

1. У каждого базового блока ровно один терминатор; терминатор — последняя инструкция блока.
2. Обычные целочисленные `add/sub/mul` считаются чистыми и математическими, если отдельно не указаны разрядность, переполнение или флаги.
3. Деление может завершиться наблюдаемой ошибкой при нуле. Его нельзя безусловно удалять или выносить без доказательства безопасности и допустимости спекуляции.
4. `print`, `store`, `volatile/atomic` и неизвестный вызов имеют наблюдаемый эффект. Вызов считается чистым только при явной пометке `pure`/`readonly`.
5. Обычный `load` нельзя объединять через потенциальный `store` или неизвестный вызов без alias/effect-фактов. Загрузки из явно корректного массива в границах считаются не бросающими исключение.
6. Все φ-функции стоят в начале блока. Для каждого непосредственного predecessor существует ровно один подписанный вход; использование incoming-value концептуально происходит на соответствующем ребре.
7. После изменения CFG необходимо обновить `pred/succ`, достижимость, входы φ и зависимые анализы, затем снова проверить SSA-инварианты.
8. Под «графом зависимостей» по умолчанию понимается SSA def-use/data-dependence graph. Memory и control dependencies требуют отдельной модели.

## Обязательные верификаторы после мутации

- каждое target/fall-through ребро соответствует терминатору;
- `v ∈ succ(u)` тогда и только тогда, когда `u ∈ pred(v)`;
- количество и подписи входов φ совпадают с непосредственными predecessors;
- каждое SSA-использование доминируется своим определением с учётом edge-use для φ;
- инвалидированные анализы пересчитаны до следующего прохода.
